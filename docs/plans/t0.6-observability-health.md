## Goal

All in `FixFlow.Hosting`, wired up in `FixFlow.API`:
- Serilog (JSON console + Seq) enriched with TraceId, OrganizationId and UserId
- a masking policy for sensitive properties (S26)
- OpenTelemetry traces and metrics → Seq over OTLP
- `/health/live` and `/health/ready` (Postgres, Blob)

DoD (from `mvp.md`):
- A request shows up in Seq as a log entry and a trace sharing the same TraceId.
- A test logs an object with `Email`, `Token` and `Password` properties, and the output shows masked values.
- `/health/ready` returns 503 with Postgres stopped and 200 when it's up; `/health/live` always returns 200.

## Decisions (2026-10-13)

| # | Question | Decision |
|---|---|---|
| O1 | Postgres connection string in dev | **Split.** Host, port, database and user in `appsettings.Development.json` (committed, non-secret). The password comes only from `Database:Password`: user-secrets locally, `Database__Password` from `.env` in the T0.11 `full` profile. Merged in code with `NpgsqlConnectionStringBuilder`. Keeps ARCHITECTURE §20 true |
| O2 | Masking mechanism (S26) | **`Serilog.Enrichers.Sensitive`** (serilog-contrib, 2.1.0, Aug 2025), configured in code. New dependency, approved by the developer. Refined in O5 |
| O3 | Where the Hosting tests live | **`tests/FixFlow.API.IntegrationTests/Hosting/`**. No new test project |
| O4 | Metrics destination | **Seq via OTLP** (`/ingest/otlp/v1/metrics`, HTTP/protobuf) with delta temporality ([Seq docs](https://datalust.co/docs/metrics-from-opentelemetry-sdks)) |
| O5 | Masking rules | **Exact property names only, no wildcards.** In 2.1.0, wildcard rules mask only string and `Uri` values; a property matching two rules throws, and Serilog then writes the event **unmasked**; their match cache is a `HashSet` written without locking; `Prop*` strips two characters instead of one. Exact rules replace the whole value of any type. Compound names (`NewPassword`, `ResetToken`) are listed explicitly; value operators (email, SAS `sig=`) cover unknown names |
| O6 | Dev hosts | **`127.0.0.1`, not `localhost`**, in `appsettings.Development.json`. Compose publishes on IPv4 only; on Windows `localhost` tries `::1` first and a refused connection takes ~2 s (measured 2083 ms), most of the 3 s health-check timeout |

## Manual steps (developer)

### A. Once, before running the API
1. Docker running, `.env` present: `docker compose up -d --wait` → four healthy services.
2. Seq API key: http://localhost:5341 → sign in as `admin` with `SEQ_FIRSTRUN_ADMINPASSWORD` → Settings → API Keys →
   Add API Key → title `fixflow-api-dev`, permission **Ingest** only → Save → copy the token (it is shown once).
3. User secrets (stored in `%APPDATA%\Microsoft\UserSecrets\`, outside the repo; `UserSecretsId` is already in the project):
   ```powershell
   dotnet user-secrets set "Database:Password" "<FIXFLOW_DB_PASSWORD from .env>" --project src/FixFlow.API
   dotnet user-secrets set "Seq:ApiKey" "<token from step 2>" --project src/FixFlow.API
   dotnet user-secrets list --project src/FixFlow.API
   ```

### B. Verify the DoD
Windows PowerShell 5.1 aliases `curl` to `Invoke-WebRequest`, so call `curl.exe`.
1. `dotnet run --project src/FixFlow.API --launch-profile http` → the console prints JSON lines.
2. Health:
   ```powershell
   curl.exe -i http://localhost:5250/health/live     # 200 Healthy
   curl.exe -i http://localhost:5250/health/ready    # 200 Healthy
   docker compose stop postgres
   curl.exe -i http://localhost:5250/health/ready    # 503 Unhealthy
   curl.exe -i http://localhost:5250/health/live     # still 200
   docker compose up -d --wait
   curl.exe -i http://localhost:5250/health/ready    # 200 again
   ```
   Optional: the same with `docker compose stop azurite`.
3. Logs ↔ traces: `curl.exe -i http://localhost:5250/` → in Seq → Events, open `HTTP "GET" "/" responded 200` →
   follow its trace (or query `@TraceId = '<id>'`) → the `GET /` span has the same TraceId. Health probes appear as
   neither traces nor Information events.
4. Metrics (optional): Seq → Metrics shows `http.server.request.duration` after ~15 s.

## Risks and gotchas
- Masking is a safety net with known gaps: a sensitive value under an unlisted name is masked only when it looks like
  an email address, card number, IBAN or SAS signature. New sensitive property names go into `SensitiveDataMasking`.
- `WebApplicationFactory` defaults to `Development` → tests use `Testing` (no Seq/OTLP, no user-secrets).
- With `Microsoft.AspNetCore` below `Warning`, ASP.NET Core logs full URLs including query strings.
- When Postgres or Azurite is down, every `/health/ready` call logs the failing check at Error (ASP.NET Core's
  health-check service). Expect noise once T0.11's Compose healthcheck polls it.
- The health endpoints must stay anonymous after T0.8 and be excluded from the SPA fallback in T0.11 (already in its scope).
