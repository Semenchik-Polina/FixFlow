# T1.5 Organization context & `ICurrentUser` — Implementation plan

**Status:** in progress, Sessions 1–3 done 2026-10-30 (Session 3's commit pending) · **Size:** L (≈ 4 sessions) · **Branch:** `feat/t1.5-organization-context` off `dev`
**Scope and DoD:** `docs/plans/mvp.md` T1.5. This file only says how. Tick T1.5 there when done.

## Goal

Since T0.9, `HttpCurrentUser` has read an `OrganizationId` claim (`FixFlowClaimTypes.OrganizationId`) that nothing adds
(P14). The only organization context so far is T1.3's trusted scope, so no request can read or write
organization-owned data yet. T1.5 adds the per-request context of ARCHITECTURE §8 and D5:
`X-Organization: {slug}` → the caller's active membership (through `HybridCache`: 60 s, tag
`user:{userId}:memberships`) → `OrganizationId` and roles on the principal and on `ICurrentUser`. A missing header gets
a 400 and no active membership a 404. Org-less endpoints are left alone. Membership changes invalidate the cache
through domain events, and integration tests get cross-tenant helpers. Every organization-owned slice from T2.1 on
builds on this.

## Decisions

**Confirmed (2026-10-28):**
- **The middleware adds the identity, with no `IClaimsTransformation`.** ASP.NET Core calls the transformation inside
  `UseAuthentication`, before `HttpContext.User` is set, so `OwnMemberships` (which reads `ICurrentUser.UserId`) can't
  run there. `OrganizationContextMiddleware` runs after `UseAuthentication`, resolves the membership, answers 400 or
  404, and otherwise adds a `ClaimsIdentity` to `HttpContext.User`. Record as a P-entry and fix the wording of §8
  step 4 and `src/CLAUDE.md` §5. D5 itself is unchanged, so no ADR is needed.

**Settled by existing rules (no question needed):**
- **Org-less marking is endpoint metadata, and "requires an org" is the default.** `MapFixFlowApi` puts
  `.RequireOrganization()` on the `/api/v1` root group. A module or endpoint calls `.WithoutOrganization()`, which works
  on a group or an endpoint, and the endpoint's own metadata wins (`GetMetadata<>` returns the last one, as with
  `AllowAnonymous`). Endpoints outside `/api/v1` (health, SPA fallback) and unmatched routes carry no metadata, so the
  middleware passes them through.
- **Anonymous callers pass through**, and authorization answers 401. Anonymous callers never learn which slugs exist.
- **One 404 for every miss:** an unknown slug, a non-member, a suspended membership, or an invalid slug format (checked
  with `OrganizationSlug.IsValid`, with no DB or cache hit). It is a bare 404, so status-code pages write the same
  Problem Details as any other 404. A missing, empty or repeated header gets a **400** Problem Details with a detail
  (`IProblemDetailsService`).
- **Roles use their own claim type** `FixFlowClaimTypes.Role = "fixflow:role"`, on an identity whose `RoleClaimType` is
  that type, so `IsInRole` and `RequireRole` work for T1.6. Org and roles are never written to the cookie.
- **Four membership events:** `MembershipCreated`, `MembershipRolesChanged`, `MembershipSuspended` and
  `MembershipReactivated`, each `(Guid MembershipId, Guid UserId)`. Separate events serve T9.2's audit log.
  `OrganizationId` is still empty at `Create`, and `UserId` is all the tag needs. One post-commit handler invalidates
  the tag.
- **The cache also stores misses.** Creation and reactivation raise events that invalidate them. Slugs never change
  (A10), so the key needs no org-level invalidation.
- **The `X-Organization` header is not documented as an OpenAPI parameter**, because `http.ts` owns it. An operation
  transformer adds the 400 and 404 responses to org-requiring operations.

## Watch out for

- **T1.6 policies must not set `AuthenticationSchemes`.** `PolicyEvaluator` would rebuild `User` without the org
  identity. Call this out in the T1.6 hand-off.
- **Middleware rejections have no `UserId` in their completion event.** The 400 and 404 are written before
  `RequestLogContextMiddleware` runs. This is accepted: the middleware's Debug log carries the user id.
- **A lookup in flight during a suspension could write the old value after the invalidation.** Check how HybridCache
  compares a tag invalidation with the entry's creation time. The sequential "next request" DoD holds either way, and
  R15 accepts ≤ 60 s.
- **The L1-only cache invalidates tags per instance.** Phase 2's replicas need Redis L2 (Phase 2 hand-off).
- **A HybridCache factory runs on the thread pool with the request's scoped DbContext.** The request awaits it, so
  the context is never used twice at once. But HybridCache stops waiting for a caller who cancels, while the factory
  goes on for any other caller of the same key. If the cancelled request's scope is disposed meanwhile, that other
  caller (the same user, the same slug, at the same moment) gets an `ObjectDisposedException`. It is rare and can be
  retried. The factory's own logs (EF Core's) also miss the request's log scope and trace, because the
  `ExecutionContext` doesn't flow.
- **Any other service that reads `IHttpContextAccessor` lazily** has the same problem inside a HybridCache factory.
  Take the `HttpContext` when the scoped service is created, as `HttpCurrentUser` does.
- **Test clients that sign in and call the convention or identity test modules** would get a 400 unless those modules
  are marked org-less.

## Found while implementing

### Session 1 (2026-10-30)

- **The abstract `HybridCache` is in `Microsoft.Extensions.Caching.Abstractions` 10.0.13**, which Application already
  gets through EF Core (via `Microsoft.Extensions.Caching.Memory`), so Application needs no new reference.
  `Microsoft.Extensions.Caching.Hybrid` 10.11.0 (2026-10-14) depends on the same 10.0.13 servicing release.
- **The resolver is tested through a test-only endpoint**, not from a DI scope. `OwnMemberships` and the cache key both
  read `ICurrentUser.UserId`, which only a signed-in request gives; faking `HttpContext` in a scope would test less.
  `GET /test-organization/memberships/{slug}` always answers 200 with `{ membership }` (null on a miss): a 404 would
  look like an unmatched route, which a signed-in caller also gets (P10). Its first version answered 404 on a miss,
  and the tests that expect a miss passed for the wrong reason.
- **HybridCache runs its factory on the thread pool without the caller's `ExecutionContext`**
  (`ThreadPool.UnsafeQueueUserWorkItem` in `Microsoft.Extensions.Caching.Hybrid`). `IHttpContextAccessor` reads an
  AsyncLocal, so inside the factory `HttpCurrentUser.UserId` was null and `OwnMemberships` found nothing: every
  lookup missed.
  - Fixed in `HttpCurrentUser`, not around the resolver: it takes the request's `HttpContext` once, when the scope
    creates it, and still reads `User` on each access (authentication and the organization context set it later).
  - The fix is general. A cached query over organization-owned data (T7's dashboard) would otherwise have run without
    an organization, through the filter's `ICurrentUser.OrganizationId`, and cached an empty result.
  - `HttpCurrentUserTests` pins it host-less, over the framework's accessor: a read queued with
    `ExecutionContext.SuppressFlow()` sees the request (red before the fix), the principal is read live, and a scope
    outside a request has no user.
  - `TrustedOrganizationScope.Open` still reads the accessor, at the call, which handlers make in the request's own
    flow.
- **HybridCache caches a null result itself**, so a miss needs no wrapper record. `Find_MissChangedWithoutEvents_StaysAMiss`
  pins it.
- **Roles are an `ImmutableArray<Role>`**, in the enum's order (as `/me` gives them), so `[ImmutableObject(true)]` on
  the record is true.
- **The handler is `InvalidateMembershipCacheHandler`**, after the repo's naming of event handlers.
- **Tests added:** 11 domain tests (each method's event, an unchanged role set, failed calls) and 14 resolver tests
  (hits, misses, invalid and upper-case slugs, cached hits and misses that skip events, and each of the four events
  invalidating), plus the 3 `HttpCurrentUserTests`. The whole solution passed: 82 domain, 148 application and
  294 integration tests, with no build warnings, and `openapi.json` unchanged.

### Session 2 (2026-10-30)

- **The header check is one list pattern**, `header is not [{ } slug] || string.IsNullOrWhiteSpace(slug)`. A
  whitespace-only value counts as empty (400). Two values joined by a comma in one header line are one value, so they
  are an invalid slug (404), not a repeated header. Session 3's table can add both rows.
- **The middleware takes its scoped services through `InvokeAsync`**: the resolver, and `ICurrentUser` for the Debug
  log's user id. `IProblemDetailsService` and the logger come through the constructor. Both refusals log at Debug,
  because neither completion event has a `UserId`.
- **`AddIdentity` changes the principal that authentication set**, the cookie ticket's own. The cookie handler copies
  the ticket for a renewal while it authenticates, before this middleware runs, so the org identity can't reach a
  renewed cookie. Session 3's "sets no auth cookie" row pins it. Whether a T1.6 policy with `AuthenticationSchemes`
  then keeps the identity (re-authentication returns the cached result, whose principal is the same object) is
  unverified: the T1.6 rule "don't set it" stands either way.
- **`HttpCurrentUser.Roles` skips a role claim it can't parse**, as `FindId` does for ids: a bad claim grants nothing.
  It checks the open scope first, so the "scope gives no roles" contract doesn't depend on the scope's own guard.
- **`OrganizationEndpoints` is org-less as a module.** An endpoint for the request's own organization added there later
  marks itself `.RequireOrganization()`: its own metadata wins.
- **Tests added now**, so the middleware isn't untested until Session 3:
  - 6 `OrganizationContextTests`: own slug, no header (400 with the header name in the detail), another org's slug
    (404), anonymous with an unknown slug (401), `/memberships` sees only the caller's org, and `/trusted-scope` is a
    500.
  - `Roles_SignedInWithoutOrganization_AreEmpty` (`HttpCurrentUserTests`) and
    `Open_SignedInWithoutContext_CurrentUserHasNoRoles` (`TrustedOrganizationScopeTests`).
  - Session 3 adds the other rows of its table. The 500 test checks only the status, so Session 3 should also check
    that the scope's guard caused it.
- The whole solution passed: 82 domain, 148 application and 302 integration tests, with no build warnings, and
  `openapi.json` unchanged.

### Session 3 (2026-10-30)

- **The helpers' shape:**
  - `TestOrganization` holds clients only, plus `As(role)` for theories over roles (`TestData.EveryRole`). A member's
    user id comes from `GetMeAsync`.
  - `MemberOfBothAsync` takes organization ids, like `AddMemberAsync`.
  - The records sit next to the extensions, as `SignedUp` does next to `IdentityClientExtensions`.
  - `JoinAsync` and `ChangeMembershipAsync` (through the aggregate) moved to `AppDatabaseExtensions`, and `MeTests` and
    the resolver tests use them.
- **An empty header value never leaves `HttpClient`.** TestServer gets no header at all, so the "empty" row would have
  been the "missing" one again. Its test builds the request on the server's side (`TestServer.SendAsync`, with the
  session's cookie). A probe showed that whitespace, a comma-joined value and a repeated header arrive as sent.
- **A per-request header replaces the client's default; it isn't merged.** The 404 test for every role relies on it:
  a merge would have been a repeated header, and a 400.
- **The scope guard's 500 is found through the trace.** The exception handler logs the exception after the request's
  log context has ended, so that event has no `UserId`. The completion event has the user but no exception. The test
  takes the completion event's `TraceId`.
- **The cookie renewal is pinned** (Session 2's open point):
  - A host of its own forces `ShouldRenew` in `OnValidatePrincipal`. That is the same `RequestRefresh` path that sliding
    expiration takes.
  - The renewed ticket, unprotected with the scheme's `TicketDataFormat`, has one identity (`Identity.Application`)
    and no organization or role claim.
- **A module's `""` endpoint has a trailing slash in `RoutePattern.RawText`** (`/api/v1/me/`). The coverage test trims
  it.
- **The OpenAPI transformer only adds what is missing** (`TryAdd`), so an endpoint's own 400 (a validation problem) or
  404 stays. It registers the `ProblemDetails` component if no operation has yet. `/me` declares a 404 of its own, so
  the test checks that `/me` has no 400, and that logout has neither.

  - 25 `OrganizationContextTests` (31 now).
  - 2 coverage tests and 2 OpenAPI tests.
  - The Application architecture test, which also checks that Identity's assembly is among the references, so the test
    reads real references.
