## Context

M1's UI is done (T1.7), but nothing checks it end to end, and the global DoD (item 8) expects CI to run E2E from T1.8 on.
T1.8 adds the Playwright harness that every later milestone extends (M2–M6 each add an E2E flow):
- a Playwright package in `tests/web-e2e/` (ARCHITECTURE §6, §19; `web/CLAUDE.md` §8)
- Mailpit and fake-data helpers
- two flows: signup → org home → sign out/in, and password reset through the Mailpit link
- a CI job that runs them against the Compose `full` profile over HTTPS and uploads the report on failure

It needs no backend code and no `gen:api`. The only runtime change is that the `full` profile can raise the auth rate
limit (P28 already anticipates this).

## Decisions

**Confirmed with the user (2026-11-02):**
1. **`ignoreHTTPSErrors: true`** in `playwright.config.ts`. Traffic still goes over TLS to https://localhost:8443
   with the exported dev cert, and secure cookies still apply. On Linux, `dev-certs --trust` reaches Chromium's NSS
   store only on a best-effort basis, so local runs and CI stay identical this way.
2. **Rate limit through a Compose variable.** The api service gets
   `RateLimiting__Auth__PermitLimit: ${FIXFLOW_AUTH_PERMIT_LIMIT:-10}`. The E2E run sets 1000, and normal `full` runs and
   demos keep S6's 10/min.
3. **Tests whose subject isn't signup sign up through the API.** A fixture POSTs `/api/v1/auth/signup` with Playwright's
   `request` fixture, which has its own cookies, so the page starts signed out. The signup UI keeps its own test.

**Taken while planning (recorded as P36 in `mvp.md`):**
- **Its own npm package**, not a `web/` devDependency. Specs outside `web/` can't resolve `web/node_modules`, and
  `web`'s eslint, tsc and prettier only see `web/`. CI installs Playwright alone, not the SPA's dependencies.
  Tooling copies `web`'s at the same pinned versions (eslint, typescript-eslint, prettier, typescript, @types/node).
  `recommendedTypeChecked` brings `no-floating-promises`, which catches a missing `await` on Playwright calls.
  The only new library is `@playwright/test`, which ARCHITECTURE §22 already lists.
- **No faker.** Fake data mirrors `tests/FixFlow.API.IntegrationTests/Fixtures/TestData.cs`:
  `user-{hex}@example.test`, `org-{hex}`, `"{prefix} {hex}"`. The hex is 6 random bytes from `node:crypto`.
- **Mailpit reads go by recipient only**, ported from `Fixtures/MailpitApi.cs`. They poll
  `GET /api/v1/search?query=to:"…"` until exactly one message arrives, then call `GET /api/v1/message/{ID}`. This keeps
  the 2 workers apart, and old mail in the persisted Mailpit volume doesn't matter.
- **`retries: 0`, `workers: 2`, `fullyParallel`, `forbidOnly` in CI.** Retries would hide exactly the flakiness that
  "3 green runs in a row" is meant to catch. Traces and screenshots are kept on failure only.
- **Accessible locators only** (`web/CLAUDE.md` §8). Password fields need `{ exact: true }`, because each field's
  "Show password" toggle also matches `getByLabel('Password')`.
- **CI builds the images with the GHA cache and starts Compose with `--no-build`.** `docker/build-push-action` tags the
  images with Compose's own names (`fixflow-api:local`, `fixflow-migrate:local`) and reads the `image` job's cache scopes.
  The E2E job runs in parallel with `image` (no `needs:`).

## Files

**New, in `tests/web-e2e/`:**
- `package.json`: `fixflow-web-e2e`, private, `"type": "module"`, `engines.node >=24`.
  - Scripts: `test` (`playwright test`), `lint` (`eslint . && prettier --check .`), `format`, `typecheck` (`tsc`).
  - Dev deps: `@playwright/test` (latest, exact pin), plus `web`'s exact versions of `@eslint/js`, `eslint`,
    `typescript-eslint`, `eslint-config-prettier`, `globals`, `prettier`, `typescript` and `@types/node`.
  - Commit `package-lock.json`.
- `playwright.config.ts`
  - `testDir: './tests'`, `fullyParallel: true`, `workers: 2`, `retries: 0`, `forbidOnly: !!process.env.CI`.
  - Reporters: `github` + `html` (`open: 'never'`) in CI, `list` + `html` locally.
  - `use`: `baseURL: 'https://localhost:8443'`, `ignoreHTTPSErrors: true`, `trace: 'retain-on-failure'`,
    `screenshot: 'only-on-failure'`.
  - One `chromium` project (`devices['Desktop Chrome']`). No `webServer`, because Compose runs the stack.
- `tsconfig.json`: copies `web/tsconfig.node.json`'s options, including `noEmit` and `types: ["node"]`, and
  includes `playwright.config.ts`, `support` and `tests`.
- `eslint.config.js`: `web/eslint.config.js` without the React plugins and the web-only restricted rules. It uses
  Node globals and ignores `playwright-report` and `test-results`.
- `.prettierrc.json` (same as `web`'s) and `.prettierignore` (`playwright-report`, `test-results`).
- `support/testData.ts`: `email()`, `organizationSlug()`, `name(prefix)`, `password()` (a random passphrase of 10+
  characters made at runtime, so no literal reaches gitleaks), and `aNewAccount()`, which returns
  `{ firstName, lastName, email, password, organizationName, slug }`.
- `support/mailpit.ts`: `class Mailpit` over an `APIRequestContext` (`http://localhost:8025`).
  - `messageTo(email)`: `expect.poll` with a 10 s timeout, then fetches the full message (`Subject`, `Text`, `HTML`).
  - `resetLinkIn(text)`: the same regex and checks as `Fixtures/ResetLink.cs`.
- `support/auth.ts`: `signIn(page, { email, password })` and `signOut(page)`.
  - Sign in: the "Email" and "Password" (exact) fields, then the "Sign in" button.
  - Sign out: the "Account" button, then the "Sign out" menu item.
- `support/fixtures.ts`: `test = base.extend` with:
  - `mailpit`: a new request context, disposed after the test
  - `account`: the result of `aNewAccount()`
  - `signedUpAccount`: `request.post('/api/v1/auth/signup', { data })`, expecting 201, which returns the account

  It re-exports `expect`.
- `tests/signup-and-sign-in.spec.ts`:
  1. On `/signup`, fill First name, Last name, Email, Password (exact), Organization name and Web address (set
     explicitly), then click "Create account".
  2. Expect the URL `/{slug}`, the h1 "Home", and the button `"{org}, switch organization"`.
  3. `signOut` → URL `/login`.
  4. `signIn` → URL `/{slug}` and the h1 "Home".
- `tests/password-reset.spec.ts`, starting from `signedUpAccount`:
  1. On `/forgot-password`, fill Email, click "Send reset link", and expect the h1 "Check your email".
  2. `mailpit.messageTo(email)`: the subject is "Reset your FixFlow password", and the link starts with
     `https://localhost:8443/reset-password#token=`.
  3. Open the link, fill "New password" and "Confirm new password" (exact), then click "Set new password".
  4. Expect the URL `/login` and the alert "Your password is changed. Sign in with the new one."
  5. `signIn` with the new password → `/{slug}`.
