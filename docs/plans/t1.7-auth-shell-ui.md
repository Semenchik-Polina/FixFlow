## Found while building (2026-11-02)

- **Zod from `zod/mini`.** Classic `zod` doesn't tree-shake and put about 45 kB (gzipped) of unused code (JSON Schema
  export, ISO and codec types) on every form page, the sign-in page included. `zod/mini` is the same package and
  the same validation core; `rules.ts` and the form schemas use `.check(...)`. Recorded in P35 and web/CLAUDE.md §5.
- **The old organization's in-flight requests are aborted, not just dropped.** The generated queries pass TanStack's
  abort signal to `http.ts`, so when the old organization's pages unmount, TanStack cancels their requests and the
  answer never lands, not even in the discarded client. Isolation test 2 checks that; test 3 still covers a refetch
  the old client starts after the URL changed.
- **`SignedInAs`** (`shared/session`): the email and a "Sign out" button on the picker, create-organization and
  "organization not found" pages, so a user with no organization (or on a wrong slug) isn't stuck.
- **`LoadError`** (`shared/components`): the error state with "Try again" for `/me`. It renders nothing on a 401,
  because `http.ts` is already loading the login page.
- **`/organizations/new` needs a session:** its `SignedInAs` reads `/me`, so a signed-out visitor goes to the login page.
- **The session query takes no abort signal** (`sessionQueryOptions()` in `shared/session/useCurrentUser.ts`, used by
  the hook and the route loaders). Found in the first manual run: signing up aborted a `GET /me`, and the API logged
  the `OperationCanceledException` from opening the connection. TanStack aborts a request that uses the query's signal
  once no component reads the query, and `/me` briefly has none when `/` hands over to the org layout (production too)
  and when StrictMode remounts the layout (development). `useCurrentUser.test.tsx` covers both, and the dev signup flow.

## Context

The backend for M1 is done: signup, login, logout, forgot/reset password (`/api/v1/auth/*`), `GET /me` (the user and
their active memberships with roles), `POST /organizations`, the organization context middleware and role policies.
The SPA is still a placeholder: `/` redirects to a stub login page, and `/:orgSlug` renders a shell with a single
"Home" link and no idea who the user is.

T1.7 turns that into a working front door and shell: the four auth pages, routing after login (one org / several /
none), an org-aware layout (switcher, user menu, role-based nav, UX-only route guards), and an "organization not
found" page. It also fixes two issues from the 2026-10-21 review of `dev`:

1. **Cross-org cache race.** `http.ts` reads `X-Organization` from `window.location` when a fetch starts. During an
   org switch, React Router loads the next route, *then* pushes the URL, *then* re-renders. Org A's page is still
   mounted after the URL already says `/b`, so a refetch in that gap (focus, interval, an invalidation) goes out with
   B's slug. A request already in flight can also land after the switch.
2. **401 on the login page.** `pathname !== globalPaths.login` misses `/login/` and `/LOGIN`, which the router renders
   as the login page, so a 401 there reloads the page and clears the form.

No backend change and no `gen:api` are needed: every endpoint T1.7 calls already exists and is generated.

## Decisions

**Confirmed with the user (2026-11-02):**
- **One `QueryClient` per organization** (recorded as **P35**). The `/:orgSlug` layout mounts
  `OrganizationQueryScope key={orgSlug}`, which creates a new client with the global client's default options. Only
  `/me` (org-less) lives in the global client. Feature code keeps using the generated hooks and keys as they are, and
  `useQueryClient()` in org pages returns the org's client, so invalidations need no change. A switch remounts the
  scope. The old client is unmounted (TanStack's provider removes its focus and online listeners) and nothing can read
  it any more. A late response, or a refetch in the gap that went out with B's slug, lands only in that discarded
  client: its result is dropped. Trade-off accepted: switching back to an org starts with an empty cache.
  No clear-on-unmount effect: under StrictMode it would run on mount and strand observers on removed queries.
- **System fonts stay** (no new font dependency).
- **The org is shown as a plain name** in the app bar, which is also the switcher button. No colour coding.
- **New dependencies:** `react-hook-form`, `zod`, `@hookform/resolvers` (already listed in ARCHITECTURE §22) and the
  dev dependency `@testing-library/user-event`. Exact versions are pinned, like the rest of `package.json`.

**Settled by existing rules or the code (no question needed):**
- **Global pages** (`shared/routing/paths.ts`, all first segments already reserved by `OrganizationSlug.Reserved`):
  `/login`, `/signup`, `/forgot-password`, `/reset-password`, `/organizations` (picker), `/organizations/new`.
- **401 handling:** a new `isPublicPage(pathname)` in `paths.ts` uses React Router's own
  `matchPath({ path, caseSensitive: false, end: true }, pathname)` against the four anonymous pages, so it matches
  exactly what the router renders (trailing slash, any case). `http.ts` redirects only when `!isPublicPage(...)`. This
  generalizes the review's "login page" to all four anonymous pages, which have the same reload-clears-the-form
  problem. Public pages never call `/me`.
- **Session hooks live in `shared/session/`**, not `features/auth/`, because every feature needs them and features
  don't import each other's internals (web/CLAUDE.md §1). The tree comment in web/CLAUDE.md gets updated.
  - `GlobalQueryClientContext` + `useGlobalQueryClient()`, provided in `App.tsx` and `renderWithProviders`.
  - `useCurrentUser()` = `useGetMe(undefined, useGlobalQueryClient())`. Generated hooks take `queryClient` as their
    second argument, so `/me` always uses the global client, even when called inside an org page.
  - `useCurrentOrganization()`: `useParams().orgSlug` + `useCurrentUser()` → the `MyMembership` (organization id,
    name, slug, roles). It throws
    outside a resolved org layout (a programming error).
  - `hasAnyRole(roles, allowed)` in `shared/session/roles.ts`.
- **Routing after login:** the index route `/` renders `HomeRedirect`. It goes to `/organizations/new` with 0
  memberships, to `/{slug}` with 1, and to `/organizations` with several. Login, signup and create-org remove the
  cached `/me` (`removeQueries({ queryKey: getGetMeQueryKey() })`) before navigating, so the layout never judges the
  new org against stale memberships.
- **Switching** goes to the other org's home `/{slug}`: record ids don't carry across orgs.
- **Sign out:** `useLogOut()`, then `redirectToLogin()` (a full page load drops every cache) on settle.
- **Route guards are UX only:** `RequireRoles roles={...}` is a layout route that renders `<Outlet/>` or
  `NotFoundPage`. Nav items carry an optional `roles`, filtered by `hasAnyRole`. Today only Home exists (every role).
  Later slices add guarded routes and items.
- **Org not found:** when the slug isn't among the user's active memberships, the layout renders
  `OrganizationNotFoundPage`. It doesn't say whether the org exists, which matches the server's single 404.
- **Waterfall:** the index, `/organizations` and `:orgSlug` routes get a static loader that starts
  `/me` without awaiting it (`void queryClient.prefetchQuery(getGetMeQueryOptions())`), so `/me` loads in parallel
  with the lazy route chunk (vercel `async-parallel`). `createRoutes(queryClient)` therefore takes the global client.
- **Forms:** RHF + Zod, one schema per form colocated with it. Shared field rules in `shared/forms/rules.ts` mirror the
  server (password 10–128 untrimmed; names ≤ 100; email ≤ 256; org name ≤ 100; slug 3–40,
  `^[a-z0-9]+(?:-[a-z0-9]+)*$`, with the server's message). Each rule names its source (`PasswordPolicy`, `User`,
  `Organization`, `OrganizationSlug`). Reserved slugs are not duplicated: the server's 400 "This slug is reserved."
  arrives through `setError`.
- **Server errors:** `shared/forms/applyServerErrors(error, setError, fieldMap?)` sends `ApiError.fieldErrors`
  (camelCase keys, confirmed by the integration tests) to their fields, with `shouldFocus` on the first one. It returns
  a form-level message for everything else: 429 → "Too many attempts…", 5xx/network → generic, otherwise
  `detail`. Create-org maps `name` → `organizationName`.
- **Test API mocking:** `src/test/server.ts` stays empty, so unhandled requests keep failing. Tests register the
  generated per-operation handlers with explicit data (`getGetMeMockHandler(me)`, …) through fixtures in
  `src/test/fixtures.ts`. Update the stale comment in `server.ts` that said the faker handlers would be spread in.

## Design direction (frontend-design)

**Subject and job.** A maintenance work-order tool used by property managers at a desk, technicians on a phone in a
stairwell (often members of several orgs), and tenants who come by rarely. The auth pages have one job: get people
in fast, with no marketing. The shell's job is to make "which organization am I in" impossible to miss, because
acting in the wrong org is the costly mistake.

**Palette** (existing tokens kept; nothing hard-coded outside `theme.ts`): service blue `#1f5fa8` (primary, app
bar), teal `#00796b` (secondary, progress), paper `#f5f7fa` (background.default), white (background.paper), MUI's
default text and error tokens.

**Type:** system UI stack. The theme sets a deliberate scale: global page title `h1` style at about 1.75rem/600 with
slightly tight tracking, the app bar org name `subtitle1` at 600, and body at 1rem/1.5. Buttons in sentence case
(`button.textTransform: 'none'`): no all-caps anywhere.

**Layout:**
```
Global pages (login, signup, forgot, reset, picker, create org, org not found)
┌──────────────────────────────┐   one left-aligned column, max ~400px, centred on paper,
│ FixFlow                      │   no card or shadow; 16px gutters at 360px
│                              │
│ Sign in                      │   title = <h1>; React 19 <title> "Sign in – FixFlow"
│ [Email                     ] │
│ [Password               👁 ] │   show/hide toggle with aria-label
│ [x] Keep me signed in        │
│ [ Sign in ]                  │   one primary action per page
│ Forgot your password?        │
│ New to FixFlow? Create an account
└──────────────────────────────┘

Org shell
┌─────────────────────────────────────────────┐
│ ☰  FixFlow   Acme Homes ▾              (PK) │  primary bar; at xs the wordmark hides, the org
├────────┬────────────────────────────────────┤  name stays (ellipsis); tab title "Acme Homes – FixFlow"
│ Home   │  page                              │
└────────┴────────────────────────────────────┘
Switcher menu: memberships (current one selected, roles as plain text) · divider · All organizations ·
Create organization.   User menu: name + email (non-interactive) · Sign out.
```
Signup groups its fields as "About you" (first and last name, email, password) and "Your organization" (name, address).
The slug field shows a `/` prefix and helper text: "Your organization's address: {origin}/{slug}. It can't be changed
later." (A10).

**Principles:** sentence case. Errors say what happened and what to do next. No decorative motion (only the existing
navigation progress bar). The org name is the largest thing in the app bar. **Review against defaults:** no
centred card with a shadow (SaaS kit), no all-caps buttons or eyebrows, no marketing side panel, no
"→" on links.

**Isolation tests.** Use a `createBrowserRouter` in jsdom, so `window.location`, and so the header, follows
navigation; `setup.ts` already resets the URL. Routes: `:orgSlug` → `OrganizationLayout` → a probe page that runs
`useQuery(['probe'], () => http('/api/v1/probe'))` and exposes its `useQueryClient()` to the test. MSW answers
`{ org: <X-Organization>, n: <request #> }`. `/me` lists orgs `a` and `b`.
1. *Switching drops org-scoped cache:* `/a` shows `a`. Switch through the switcher → `/b` shows `b` (header `b`) and
   never `a`. Back to `/a` → a new request goes out (cold cache).
2. *A's in-flight result is dropped:* hold A's refetch response (a deferred promise in the handler), switch to `b`,
   then release it. B shows only its own response, and B's client never holds A's data.
3. *A's refetch in the gap is dropped:* after the switch, `aClient.refetchQueries({ type: 'all' })`. The request goes
   out with `b` (expected: the URL is `/b`), and its result (`n`) never shows in B's page or B's client.
