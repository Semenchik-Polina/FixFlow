# T2.3 — Properties & units UI (+ a property's time zone must belong to its country)

**Status:** done 2026-11-25 (both sessions).

**Changed while building (session 2):**
- One shared `shared/forms/FormAutocomplete.tsx` for both the country and the time zone, not `CountryField` +
  `TimeZoneField`.
- Dialogs (`PropertyFormDialog`, `UnitNameDialog`, `ConfirmDialog`) are open while mounted: callers render them only
  when they show, so each opening starts fresh, without reset effects. They lose the closing fade.
- The property page owns the units query (`UnitsSection` shows it), so the archive confirmation can say how many units
  go with the property.
- `AppShell`'s nav items use `end` for Home only, so Properties stays selected on a property's page.
- Page tests load the page modules in `beforeAll`: the lazy chunk with the DataGrid could outlast the first `findBy`.

## Context

T2.2 shipped the property and unit endpoints (Manager + Admin only), and the generated client has their hooks
(`useListProperties`, `useGetProperty`, `useCreateProperty`, `useUpdateProperty`, `useArchiveProperty`,
`useListUnits`, `useCreateUnit`, `useRenameUnit`, `useArchiveUnit`). Nobody can use them from the SPA yet.
T2.3 (`docs/plans/mvp.md:512`) adds:
- a properties grid with server paging
- a create/edit dialog with a time-zone autocomplete
- a detail page listing the property's units
- archive confirmations

DoD: component tests cover validation and server error mapping, and an E2E test where the admin creates a property
and a unit.

While planning, the developer added one rule: **a property's time zone must be one of its country's zones.** Today
P37 accepts any place zone with any country, so Poland with America/New_York passes. The server enforces the new
rule, and the dialog offers only the chosen country's zones. This makes T2.3 one vertical slice (domain → endpoint
→ tests → `gen:api` → UI, CLAUDE.md §5.2) in two sessions. The size goes from M to L.

## Decisions

Developer's answers (2026-11-25):
- **Units:** create, rename and archive. Create and rename share one dialog with a single name field.
- **Search:** a name search box above the properties grid, debounced, sends `name`.
- **Property actions:** Edit and Archive live on the detail page only. The grid has New property, and each row
  links to its property's page.
- **Country ↔ zone:** all countries stay allowed. The server rejects a zone outside the address's country, and the
  dialog offers only that country's zones.

Settled by existing rules or code:
- Add `@mui/x-data-grid` (community, MIT). It's already in ARCHITECTURE.md's frontend dependency list (line 887)
  and in web/CLAUDE.md §4. Pin the version whose peerDependencies match `@mui/material` 9.5.
- No `Idempotency-Key` on property or unit creates. A8 covers only requests and comments.
- Archiving a property also archives its units (P38). The confirmation says so.
- The rule changes a decision (P37, ARCHITECTURE §11 line 512), so it gets ADR 0008, a P39 row and a §11 update
  (CLAUDE.md §5.5).

My calls (minor; correct them on review):
- **Zones come from the server, not the browser.** A new `GET /api/v1/properties/time-zones` returns
  `[{ countryCode, timeZones[] }]` from NodaTime. Why not the alternatives:
  - The browser's per-country list (`Intl.Locale#getTimeZones`) isn't in every browser and can disagree with
    NodaTime.
  - A hard-coded map in the SPA would drift from the server.

  This drops the earlier `Intl.supportedValuesOf` plan, along with its UTC/`Etc` filtering and browser-zone default.
- **Country becomes an autocomplete ⚠ (this reverses your earlier text-field answer).** You picked the text field
  because an autocomplete needed a hard-coded country list. The endpoint now supplies that list, so the autocomplete
  costs nothing extra. Options are shown as "Poland (PL)" (name from `Intl.DisplayNames`, sorted by name).
- **Choosing a country** fills the zone when the country has exactly one (PL → Europe/Warsaw). Otherwise it clears
  the zone, unless the current zone is still in the new list. The zone field is disabled until a country is chosen.
- **Listing vs accepting.** The picker lists a country's zone.tab ids, which name places users recognize (NO →
  Europe/Oslo). The server accepts more:
  - the id or its canonical zone listed for that country in zone.tab
  - the canonical zone's zone1970.tab entry naming the country
  
  So aliases (`Europe/Kiev` for UA) and shared zones (`Europe/Berlin` for NO) stay valid, and P37's "aliases stay"
  still holds for API clients and stored data. When editing, a stored id that isn't in the list is added to the
  options.
- **The time-zones endpoint is org-scoped** with `Policies.CanManageProperties`, which only property managers need.
  So it isn't added to the org-less allow-list. It's a fixed reference list of about 250 rows, so it isn't paged
  (the "always paginate" rule is for database queries). The client caches it with `staleTime: Infinity`.
- **Units list:** also a server-paged DataGrid, with Rename / Archive row actions (`aria-label`ed icon buttons).
- **Page and search state** live in `useState`. Shortcut: Back from a detail page returns to page 1 with an empty
  search. Move them to search params if that annoys anyone.
- **After creating a property,** go to its detail page. That's where units get added, and it's the E2E flow.
- **Blank `line2` / `postalCode` are sent as `null`.** The OpenAPI schema marks both `null | string`.
- **Name cells are `RouterLink`s,** not clickable rows, so they're keyboard-reachable. Sorting and column filters are
  off, because the API orders by name and takes no sort parameter.
- **No migration.** There's no schema change. Properties stored before the rule with a mismatched pair (dev data
  only, nothing is released) must fix the zone on their next edit, and the field error says so.

## Session 1: backend rule + time-zones endpoint ✅

Load `dotnet-best-practices` first.

1. **Domain** in `src/FixFlow.Domain/Properties/PropertyTimeZone.cs`. Reuse `PlaceIds()`'s `TzdbDateTimeZoneSource` data.
   - `ByCountry` (`IReadOnlyDictionary<string, IReadOnlyList<string>>`): zone.tab ids per country, sorted, frozen.
   - `IsValidFor(string timeZoneId, string countryCode, out string? error)`: the matching rule above. The message is
     written for the user, e.g. "Choose a time zone in the property's country."
   - `Property.Create` / `Update` (`Property.cs:47,57`) check it after the existing zone check and throw
     `DomainException`. A failed `Update` leaves the property unchanged.
2. **Validation:** `PropertyValidationRules.TimeZone` gains the cross-field check, used by both
   `CreatePropertyValidator` and `UpdatePropertyValidator`. It runs only when the zone and the country are each
   valid, so there's no double error, and the error goes on `timeZone`.
3. **Endpoint:** `Properties/ListPropertyTimeZones/` (query + handler returning `IReadOnlyList<CountryTimeZones>`,
   where `CountryTimeZones(string CountryCode, IReadOnlyList<string> TimeZones)`). In `PropertyEndpoints.cs`:
   `group.MapGet("/time-zones", …)` with `.WithName("ListPropertyTimeZones")`, `CanManageProperties` and declared
   responses. The `{id:guid}` constraint keeps the route from clashing.
4. **Tests**
   - Domain `PropertyTimeZoneTests` cases:
     - PL+Europe/Warsaw ✓, PL+America/New_York ✗
     - UA+Europe/Kiev ✓ (alias), NO+Europe/Oslo ✓, NO+Europe/Berlin ✓ (zone1970), IN+Asia/Calcutta ✓
     - every country in `Address`'s set has ≥1 zone in `ByCountry`
     - every listed zone passes `IsValid` and `IsValidFor`
   - Domain `PropertyTests`: Create/Update with a mismatched pair throws.
   - `PropertyValidatorTests`: a mismatched pair fails only on `TimeZone`. An invalid country doesn't also fail the
     zone. Fix line 23 to use a UA address with `Europe/Kiev`.
   - Integration `PropertyEndpointsTests`:
     - create and update with a mismatched pair → 400 with a `timeZone` field error
     - `GET /properties/time-zones` as Manager/Admin → 200, includes `PL: [Europe/Warsaw]`
     - Technician/Tenant → 403
     - a Manager of A sending B's `X-Organization` → 404 (cross-tenant)
   - Fix `PropertyPersistenceTests.cs:32` (IE address with Europe/Warsaw → `Europe/Dublin`, or a PL address).
5. **Contract:** `dotnet build` (writes `openapi.json`), then `npm run gen:api` in `web/`.
6. **Docs:**
   - `docs/adr/0008-property-time-zone-belongs-to-country.md` (short)
   - ARCHITECTURE.md §11 line 512: "…and one of its address country's zones"
   - `docs/plans/mvp.md`: a P39 row (amends P37); T2.3's scope gets the rule and the size L

## Session 2: UI ✅

Load `vercel-react-best-practices` and `frontend-design` (within MUI + theme tokens) first.

1. **Dependency:** `npm i -E @mui/x-data-grid@<matching>`. Imports go by path, as the lint rule requires.
2. **Roles, routing, nav**
   - `shared/session/roles.ts`: `propertyManagerRoles = ['Admin', 'Manager']`, mirroring `Policies.CanManageProperties`.
   - `app/router.tsx`: under `:orgSlug`, a `RequireRoles` layout route (its first user) with lazy `properties` →
     `PropertiesPage` and `properties/:propertyId` → `PropertyDetailPage`.
   - `app/shell/navItems.ts`: a Properties item (`ApartmentOutlined`, `roles: propertyManagerRoles`).
3. **Shared** (each has a later user in M3–M5)
   - `shared/components/ConfirmDialog.tsx`: title, message, confirm label, `onConfirm(): Promise<unknown>`. Confirm is
     disabled while pending. A failure shows an `Alert` in the dialog (`LoadError`'s wording), and the dialog stays
     open.
   - `shared/hooks/useDebouncedValue.ts` (~8 lines).
   - `shared/forms/rules.ts`: `propertyName` (100), `addressLine` (200), `optionalAddressLine` (200), `city` (100),
     `postalCode` (optional, 20), `countryCode` (required), `timeZone` (required), `unitName` (50). Each limit names
     its source, as the file does. Messages go in `shared/strings.ts`.
4. **`features/properties/`**
   - `strings.ts`: all UI text (D27).
   - `hooks/usePropertyTimeZones.ts`: wraps `useListPropertyTimeZones` with `staleTime: Infinity` and returns a
     `Map<country, zones>` plus the countries sorted by display name.
   - `components/CountryField.tsx` and `components/TimeZoneField.tsx`: RHF `Controller` + MUI `Autocomplete`, labelled
     "Country" / "Time zone". They show the field error as helper text and pass the input ref so
     `applyServerErrors` can focus them. `TimeZoneField` takes the country's zones, and is disabled without them.
   - `components/PropertyFormDialog.tsx`: create (no `property`) or edit. Fields: name, address line 1/2, city, postal
     code, country, time zone. The zod schema is colocated and built from `rules`. Field names match the API.
     - Country change logic per "My calls", via `useWatch` + `setValue`.
     - `applyServerErrors(error, setError, { name: 'name', 'address.line1': …, 'address.line2': …, 'address.city': …, 'address.postalCode': …, 'address.countryCode': …, timeZone: 'timeZone' })`.
     - The root error shows in an `Alert`. Submit is disabled while submitting. The form resets on each open.
     - While the zones query loads, the fields are disabled. If it fails, a `LoadError` shows in the dialog.
     - On success it invalidates `getListPropertiesQueryKey()` + `getGetPropertyQueryKey(id)`, then calls
       `onSaved(property)`.
   - `components/UnitNameDialog.tsx`: create or rename, one `name` field, `{ name: 'name' }` mapping. That covers the
     400 and the duplicate-name 422. Invalidates `getListUnitsQueryKey(propertyId)`.
   - `pages/PropertiesPage.tsx`: h1 "Properties", New property (dialog → navigate to the detail page), a search
     field (debounced → `name`, resets to page 0).
     - Data: `useListProperties({ page: model.page + 1, pageSize, name })` with `keepPreviousData`.
     - DataGrid: `paginationMode="server"`, `rowCount` from `totalCount`, `pageSizeOptions [25, 50, 100]`
       (API max 100), a skeleton loading overlay, and no-rows text for empty vs no match.
     - Columns: name (link), address (line 1, city), time zone.
     - `LoadError` on failure.
   - `pages/PropertyDetailPage.tsx`: `useGetProperty(propertyId)`. A 404 shows `NotFoundPage`; loading shows a
     skeleton.
     - Top: h1 the name, then the address, country name and time zone.
     - Edit opens the dialog. Archive opens `ConfirmDialog` ("also archives its N units", N from the units query's
       `totalCount`). On success it removes the detail query, invalidates the list and navigates to the list.
     - Units: h2 "Units", an Add unit button, and a server-paged grid with Rename / Archive row actions. Archive goes
       through `ConfirmDialog`.
